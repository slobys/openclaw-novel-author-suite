# Resumable Workflow Handoff

Use this procedure when a multi-stage creative workflow must continue asynchronously or resume after a pause or interruption.

1. Define the completion target before work starts. Record artifact-level acceptance checks, durable constraints, the explicit stop boundary, and out-of-scope actions. Convert requirements such as dimensions or aspect ratio into checks against produced artifacts. **Check:** durable project state names the target, checks, boundary, and exclusions.

2. Write an atomic checkpoint after every stage. Record outputs, stage status, validation results, and the first unfinished stage in one progress record. Classify work as completed, partial, not started, running, or held without relying on chat history. **Check:** the checkpoint contains an unambiguous resume cursor and evidence for every completed stage.

3. Apply control changes before acknowledging them. For a pause, stop or disable owned workers, queue entries, and continuation watches that could cross the boundary; verify downstream submission state; retain validated artifacts and prepared job packages. For a full stage remake, freeze the old branch, recoverably archive its assets and uncommitted jobs, preserve only explicitly allowed continuity references, create fresh context at the requested phase, and hold later stages. **Check:** no superseded entry can run, unavoidable activity is listed, the intended entry is the only active one, and the checkpoint names retained or archived material plus the resume cursor.

4. Validate and assign the handoff before dispatch. Confirm that each claimed completed artifact exists and passes its stage gate. Persist a continuation contract beside the checkpoint with the project location, governing procedure, progress owner, delivery target, authoritative workflow or job identifier, first unfinished stage, durable constraints, stop boundary, and next-dispatch permission. If submission creates the identifier, update the contract before the turn ends. **Check:** durable state identifies the validated checkpoint, accepted job, record to close, delivery target, and dispatch boundary.

5. Arrange a push-based continuation before the foreground turn ends. Prefer an available completion callback routed to the recorded delivery target rather than foreground polling. Track control-plane acceptance, continuation liveness, and downstream execution separately: acknowledgement proves acceptance; a live callback path proves liveness; only concrete downstream evidence such as an output location and processing manifest proves execution. After dispatch, reconcile one snapshot of durable workflow state with the queue or control plane, including active stage identifier, completed and active counts, next-stage cursor, and entries beyond the stop boundary. **Check:** the continuation path is accepted, execution claims cite concrete evidence, durable state and queue agree, and no entry crosses the boundary.

6. Resume from durable evidence. Reread the governing procedure, continuation contract, and checkpoint; corroborate callback evidence with local workflow state; rerun relevant artifact gates; inventory completed, running, pending, and held outputs. Continue at the first unfinished stage, avoid repeating validated work, and keep later stages held while the current stage processes. **Check:** callback evidence, gate results, queue positions, and the resume cursor agree before checkpoint advancement.

7. Report the highest state proved by durable evidence. Label a created workspace, active session, or `running` queue entry as dispatched or accepted until downstream submission is confirmed; label processing only after concrete downstream evidence appears. Separate work completed now, accepted for continuation, confirmed in downstream processing, and unfinished. Include the continuation identifier when available, scope any completion counter to its bounded objective, and name the unfinished stage and next trigger. **Check:** the report’s headline and bullets use the same evidenced state, and accepted or processing work cannot be mistaken for final artifact completion.

8. Close and deliver idempotently after the final artifact passes its gates. Mark all waiting steps complete, persist closure time and completed state, and remove obsolete continuation watches. If legacy checkpoints lack an owner, match candidate records by stable workflow identifier, close every matching record still waiting only for the final artifact, and persist the resolved owner. Resolve each artifact link in the recipient's active workspace; when its source is outside that workspace, create and verify a review copy there before delivery through the arranged push path. **Check:** repeated completion preserves the closed state, no matching record remains waiting, no active watch remains, every delivered link is previewable, and delivery confirms the final checkpoint, closure, and excluded actions.
