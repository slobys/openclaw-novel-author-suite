# 自动长篇小说：持续优化路线

## 目标与保证边界

目标是自动写作、校验、修订和恢复的闭环，不是承诺任意模型输出永不出错。

- 程序层可以确定性验证：引用是否存在、生命周期是否允许、版本是否一致、流程是否闭环。
- 语义层仍须核验：线索是否真正写入正文、回收解释是否成立、人物动机和推理是否可信。
- 阅读层单独评测：主线推进、伏笔公平性、角色主动性、节奏和类型体验。

Hash 和审稿 `pass` 是证据绑定与流程条件，不是文学正确性的证明。

M4 保留“上一章 Commit + Closure + Integrity 完成才能开始下一章”的约束。不能为了连续写作放弃可取消和故障终态，不能把无限重试当自治。

## 已有缺口与首轮取舍

基线使用临时合成项目，未接触真实小说：

1. `continuityDelta` 对未知伏笔 ID 宣称 payoff，可出现 `paid` 且 `plantedChapter=null`。
2. 伏笔后续更新省略 `plantedChapter` 会丢失原埋设章。
3. 因果引用缺失 ID、多节点环、已发生事件依赖未发生的 planned 原因，仍可写入。
4. 权威台账写入后，同章 prepare 快照仍复用旧包。
5. 已声明伏笔变化仍可将 Closure 的相应操作标 skipped 并通过原完整性检查。

M1 优先解决前三项及其提交入口；M2 跟进缓存、上下文遗漏和声明/闭环一致性。首轮不声称解决所有知识状态、主线漂移或文学推理问题。

2026-10-08 作者补充章长递减、每章高等待/Token和内容同质化，M2A优先接入写作体验。阶段成长使用“目标—阻力—选择/代价—伏笔桥梁—新阶段”，世界展开也可指知识、制度与关系，不强制村庄到宇宙的换地图公式。旧M2上下文/Closure目标继续保留；精简不取消审稿、Hash、CAS、Closure或可恢复提交。真实模型十章A/B、实际Token费用及阅读质量提升仍未验证。

叙述章节号不是世界时间：合法倒叙、插叙和同章因果必须保留；时间推断须依赖明确语义/状态证据，不能机械比较章号。

## 每轮执行闭环

1. 读取项目记录、研究和当前分支状态，确认没有其他执行者修改同一范围。
2. 从有证据的缺口选一个有界目标，更新技术方案和测试期望。
3. 在隔离开发分支实施，使用合成数据；不得更改运行中插件、作者小说或默认分支。
4. 验证正常路径、对抗路径、兼容和恢复，再独立审查；发现缺陷继续修复。
5. 保存验收记录与可审查改动；更新进度和下一项。正式合并、版本发布和生产部署由用户决定。

## 评测记录要求

- 确定性程序测试与模型语义评测分开报告。
- 指标必须给出真实分母、判定规则、版本与失败案例；不以测试数量推算小说质量。
- 线索回收需分别检查埋设来源、回收来源及解释链，而非仅凭状态 `paid`。
- 世界事实、人物信念、读者可见信息分别表示；可靠来源、猜测与谎言不可混合。
- 主线调整应说明影响和原因，优先改未来计划，不静默覆写已提交历史。
- 精简资料包无法容纳关键约束时，报告缺失并进行窄查询；不能把被截断事实当不存在。
