# M2A 写作体验：稳定章长、精简生产与差异化阶段规划

研究日期：2026-10-08。角色：Researcher。状态：一手资料核验与建议完成；**不是模型生成实验、性能基准或文学质量验收**。

输入：本轮写作体验需求、[前轮一致性研究](RESEARCH-NARRATIVE-CONSISTENCY.md)、[README](../README.md)与定点源码。源码观察固定于 `e1ae51c79f5502c08668f6f87288cffdd719abfd`；工作分支 `improve/writing-experience-20261008`。前轮八项研究不重复展开，本轮新增五项一手来源。

## 1. 结论与边界

1. **稳定的是项目长度契约，而不是每章机械等长。** Writer、Reader 与服务端使用同一正文汉字目标区间；本地精确计数区分硬下限与创作目标，不让第十章实际变短反向修改目标。
2. **先减少重复工作，不减少独立判断。** 资料快照、角色包、Writer 随稿审计、两名 Reviewer 并行及单次收尾已有基础，应核查实际执行是否遵循，再补缺口；不能重新包装已有能力为新增优化。
3. **阶段成长是可选的类型结构，不是所有小说的普遍公式。** 成长可体现能力、认知、关系与责任变化，也可经历失败和代价；阶段转换要兑现可追踪的铺垫并继承旧关系、旧伤害、旧承诺。
4. **差异化应比较章级叙事功能及解决机制。** 换形容词、地点或对手名字不足以改变同一结构；合法回调和同题深化也不能被一律拒绝。

以上是本项目设计建议。所核验研究不能证明中文长篇第 1—10 章必然稳定、自动规划必然精彩，或本项目已降低 Token、费用、延迟。本轮不新增供应商、训练模型、启动付费写作、处理真实小说或生产部署。

## 2. 五项一手证据：研究事实与设计推论分开

### 2.1 LongWriter：长输入不等于长输出，分段有成本

LongWriter 预印本始于 2024，作者仓库标注 ICLR 2025。其受测模型与受控训练实验表明，长上下文能力不自动带来相应长输出；AgentWrite 先规划分段内容与长度，再串行写作、携带此前输出。另一路结果来自加入长输出训练数据，不能算普通提示词的效果。[论文 §2–3](https://arxiv.org/html/2408.07055v1)、[ICLR 正式论文](https://proceedings.iclr.cc/paper_files/paper/2025/file/59f278de1619bdb6b53fd04e8e0976e0-Paper-Conference.pdf)、[作者代码](https://github.com/THUDM/LongWriter)。

- 可借鉴：把章目标转成少量必要场景及其篇幅预算；长度与内容质量分别评测。
- 不可外推：论文受测模型的长度现象不是本项目逐章缩水的已定位根因；其中文字符/英文词口径不等于本项目“正文汉字”。串行分段会增加调用与历史输入，不是免费提速。
- 本地推论：优先在现有 Writer 同一轮内表达场景预算；只有明显缺少必要场景且预算允许时才有限定点修订，不为正常章节默认增加多段模型调用。

### 2.2 多类型长度控制：区间可确定校验，但论文包含训练

Findings of ACL 2024 的 *Prompt-Based Length Controlled Generation with Multiple Control Types* 区分等于、超过、小于、区间长度要求，以标准约束和规则奖励进行 RL 微调与候选过滤；实验主要为 CNNDM/NYT 新闻摘要及短 token 目标，并非中文数千字小说。[正式论文](https://aclanthology.org/2024.findings-acl.63/)、[正文 §3–4](https://arxiv.org/html/2406.10278v1)。

- 可借鉴：将长度要求规范成可计算约束，避免让另一个模型估算字数。
- 不可外推：标题中的 prompt-based 不表示只换一句提示就复现论文效果；候选过滤还需额外生成，训练不在本轮范围。
- 本地推论：沿用已有结构化 `writingContract`，计数和区间状态由服务端提供；不引入新的模型“长度检查员”。

### 2.3 Lost in the Middle：完整上下文不等于有效使用

TACL 2024 论文在多文档问答、键值检索中改变证据位置与上下文长度，发现受测模型对中间位置证据的利用可能弱于开头/结尾；长窗口不保证稳健使用全部信息。[正式论文](https://aclanthology.org/2024.tacl-1.9/)、[作者代码与数据](https://github.com/nelson-liu/lost-in-the-middle)。

- 可借鉴：评测不仅检查“资料包里有没有事实”，还检查关键证据在不同位置时能否被使用。
- 不可外推：问答/检索结果不是小说品质实验，也不说明现用模型都有同样幅度的位置效应；删掉历史越多越好并非论文结论。
- 本地推论：按当前人物、阶段、因果依赖和到期承诺选择资料，保留必需证据与出处；将本章关键约束清楚分组，预算不足显式报告，不静默裁掉旧承诺。

### 2.4 AI 创意与群体多样性：有同质化风险，不等于证明章内循环

Doshi 与 Hauser 的 Science Advances 2024 在线实验让人类写八句短故事，部分人可获得 AI 起始创意。AI 辅助故事被评为更有创意/更好读，但在其群体相似度分析中也更接近彼此。[出版页](https://doi.org/10.1126/sciadv.adn5290)、[作者预印本正文与方法](https://arxiv.org/pdf/2312.00506)。

- 可借鉴：个体可读性与作品集合的多样性是不同目标，不能用一个质量分替代两者。
- 不可外推：这是人类受 AI 创意辅助的短故事实验，不是自治模型写中文长篇；故事间 embedding 相似也不是章节间“打脸—升级”循环的直接验证。
- 本地推论：在规划层提供不同章功能、冲突来源、代价与解法；用已有签名台账发警示，语义复核后再决定未来章节调整，不靠词语重合宣称文学重复。

### 2.5 官方 Prompt Caching：供应商机制不等于本地资料缓存

Claude 官方文档说明其 Prompt Caching 复用一致前缀，具有 TTL、最小长度、缓存写入/读取计费和失效规则；可从 usage 的缓存字段核查命中，并行冷请求不保证共享已创建缓存。[官方文档：工作原理、限制与 usage](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)。

- 可借鉴：稳定资料与本章变化分开，未来如现用链路确有缓存能力，按真实 usage 验证。
- 不可外推：本项目 `prepareSnapshotCache` 是本地快照复用，不能据此宣称供应商少收费；Prompt Caching 不减少模型请求次数、逻辑上下文长度或输出 Token。本报告不引用价格百分比或保证命中率。
- 本地推论：本轮先优化实际资料选择与重复调用。供应商能力未核验前不新增接入；不为追求缓存命中而串行两个原本可并行的 Reviewer。

访问日期均为 2026-10-08。论文版本与作者仓库可能变化，复现时需固定版本；本轮只阅读，不安装或执行作者代码。

## 4. 可交给工程与 QA 的设计建议

### 4.1 稳定章长：内容预算、确定计数、有限修订

- 规划少量必须完成的场景功能：行动/观察、关系变化、后果承受等；篇幅预算随功能而异，不固定“对白三百字”式模板，不要求每章新增伏笔。
- 使用同一正文汉字计数器，标题、标点、JSON 不计入；原始字符数、汉字数、模型 token 分开记录。
- `低于硬下限 / 已达下限但低于目标 / 目标内 / 超目标` 分开报告。低于目标可提示，不能与硬下限失败混为一谈。
- 若需修订，指定缺失的场景变化及已有事实边界，限制轮次；重新计数，并按新正文 Hash 重验。禁止循环补字、重复总结或静默删除/修改旧章。
- 漂移警示对照配置目标而非最近实际平均数；窗口/阈值交给工程明确且可配置。合理短章需要显式创作决策，不通过悄悄降低整本目标实现。

这是 §2.1–2.2 的工程适配，**没有论文证明有限修订既能增加篇幅又同时减少成本**；这两个目标可能冲突，应分别记账。

### 4.2 精简生产：四种节省分别计量

| 优化类别 | 可能减少什么 | 不能据此宣称什么 |
| --- | --- | --- |
| 本地快照与资料选择复用 | 文件读取、重复组包、重复扫描 | 模型调用数、付费 Token 已降低 |
| 角色资料与必需证据选择 | 实际提交的冗余上下文 | 所有旧事实都安全，或文学质量提升 |
| 去重编排/并行审稿 | 重复模型请求、部分串行等待 | 审稿质量相同已实测；并行必然更便宜 |
| 供应商前缀缓存 | 满足条件时的预填充工作/计费 | 输出变短、调用变少、上下文上限扩大 |

完整性优先：保留 17 类审计、真实独立审稿、Hash/CAS、幂等、Closure、取消与恢复。正文变化使旧审稿失效；未改正文的格式修复才可能复用同版本结果。完整审查与局部重复读取是不同事项，不因“快”省掉必需检查。

### 4.3 阶段成长与桥梁：可选结构，保留债务

建议每阶段表达：`目标 / 已知边界 / 成长维度 / 主要阻力 / 代价 / 关系变化 / 章功能组合 / 铺垫引用 / 进入下一阶段的条件 / 必须继承的旧承诺`。这些是规划标签，**不是新增 API 的既定字段**。

- 当前阶段有局部目标与结束条件；下一阶段由已发生变化或已有铺垫开启，不只是换一个更强对手。
- 成长不必单调增加能力：认清误判、失去支持、学会合作、承担责任、接受能力边界均可成为变化。
- 桥梁要指向读者见过的线索/关系/规则，以及主角有因果前提的选择；内部计划不是正文已经埋下的伏笔。具体证据沿用前轮报告的 seed/payoff 来源区分，不再研究一遍。
- 世界展开可扩大知识、关系网络、制度约束、伦理责任或时间视野；**同一地点也可以持续展开世界**。升级不清零旧关系、伤势、信誉损失和未兑现承诺。
- 阶段内允许调查、尝试、失败、修复、承压、回收等不同功能；不要求每章都经历“成长—埋伏笔—解锁”。
- 没有阶段规划的旧书继续运行；只有当前阶段与本章相关的下阶段桥梁进入 Writer 包，不每章反复投喂全书阶段长文。

上述是老板要求的产品设计解释，不宣称来自一条普遍叙事定律。它可利用前轮 DOC/DOME 的分层规划思想，但不意味着论文证明该成长循环最优。

### 4.4 差异化：比较结构，不制造随机变化

建议章签名覆盖：`主要功能 / 开场方式 / 冲突来源 / 解决机制 / 胜负与代价 / 关系变化 / 情绪转向 / 收尾方式`。先复用现有台账，兼容缺失字段；Writer 的计划签名与正文实际签名应区分，计划不同不证明写出来不同。

- 多个相邻章重复同一功能+冲突+解法时警示；变化一个地点或一个动词不自动解除。
- 合理回调、仪式性重复、相同冲突下发生新的认识/代价/关系转向是允许的正例。词汇相似度只能辅助定位，不能独立裁决语义重复。
- 调整以未来规划为先：例如下一章从“正面取胜”转为“处理胜利的关系后果”，必须服务本书主线，不随机换风格，不无依据改历史正文。
- 篇幅、冲突密度、情绪强度与结尾悬念分开变化；不是每章都要更激烈，也不强制每章不同。

§2.4 只提供关注同质化的动机，没有验证本地签名规则的准确率；需要原创正反例及后续读者评价。

## 5. 验收与未实测项

### 工程可先验证的最小集合

| 案例 | 必须展示的证据 |
| --- | --- |
| 同配置第 1/10 章 | 目标区间一致；低于硬下限拒绝；下限以上但偏离目标可诊断；标题/标点不补足汉字 |
| 配置/阶段改变 | 新 Writer 包使用新值；相关快照失效；未静默迁移或覆盖旧项目 |
| 早期桥梁与旧代价 | 添加许多无关新记录后仍携带本章必需旧证据；无法装下时显式诊断 |
| 旧书没有阶段计划 | 不要求新增字段即可继续原流程 |
| 相同章结构换表面词 | 发重复警示；有新因果、关系/代价变化的回调不硬拒绝 |
| Writer/双审/finalize 合成执行 | 必需审计/独立会话/Hash 绑定保留；列调用序列及重试原因，不把一次 Engine 工具调用等同一次模型请求 |
| 正文修订与格式修复 | 前者使旧审稿失效；后者不触发无关的重新写作；预算耗尽可恢复而非无限循环 |

这些是建议用例，**本研究未执行测试**。合成流程仅能证明工程行为；字符/字节数不是模型 Token，也不是费用。

### 后续真实体验评测需另行安排

以原创中文前提、相同模型版本/参数、相同章节计划与预算，对照基线和候选流程，至少观察至用户报告的第十章；篇幅完成率、逐章目标偏差/趋势、修订轮数、主线兑现、关系/代价延续与读者节奏评价分别报告。题材不同的作品不用同一升级模板。

成本与速度需采集真实 input/output/cache usage、模型请求次数、各阶段墙钟、失败/取消与未完成情况；不能只计成功章节或把缓存读 Token 当零。模型 Judge 与人工阅读的结果分开；质量与多样性分别盲评，不用单元测试或签名“通过”冒充精彩程度。

本项目目前未实测：用户短章原因、优化后的真实 Token/费用/延迟、十章以上的长度稳定性、语义重复警示误报漏报、成长规划的中文长篇文学收益，以及现用链路的供应商缓存支持/命中。没有据此报告收益百分比。
